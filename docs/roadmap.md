# 音视频构建路线

## 已交付的共同底座

工程 → 章节 → 独立句段；正文／表现、素材版本、时间点评论、验收、任务快照、图配置、本地持久化、音视频预览和连播。启用句段的音频增益与停顿混音导出。TXT／Markdown／JSON／完整媒体 ZIP 的导入，默认追加与引用重映射，v1 备份迁移和可携带工程 ZIP 导出。

## 下一阶段：真正执行生成任务

在现有任务合同外增加本地 worker 适配器。先对接当前已授权的 MiniMax 网页操作，回传真实进度／失败／扣点证据；同时核实 MiniMax 官方 API 的账户、本人音色复用及计费；通过已授权短句实测后再考虑 API 适配，网页与 API 共用任务合同。再支持其他生成提供者。不能默认改成收费 API。先定义任务领取与取消，防止多 worker 重复付费。

## 视频构建

已有同句段节点旁白／画面与共同零点预览。后续扩展为统一时间线：时间线片段通过现有素材版本 ID 关联画面、音轨、字幕与画幅，新增剪入剪出、偏移、字幕校时与配乐混音。章节继续组织句段，不能再建一套媒体版本或任务权威。渲染作为独立服务适配 Remotion、HyperFrames 或 FFmpeg，工程仍是唯一权威。导出 MP4 前加入真实渲染、抽帧、音画同步与可播放验证。

## 持续使用

多工程列表、素材回收与存储监测。可携带 ZIP 已提供，后续完善大工程流式打包与分卷。保留旧版，清理前检查引用；在线托管与多人权限另行设计。

## 兼容层退出

当前旧章节执行路由仅为 v1 → v2 的一次发布兼容层。新调用方统一使用片段路由，记录旧调用方迁移完成后，在下一轮格式迁移中删除旧别名并运行迁移与素材回归。
