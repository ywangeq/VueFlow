## 后续新视频如何试用

开始新的已授权视频制作时，先读取本流程，评估选一小章进入工作台；可从开场的 2–3 个句段试跑，再扩大至整篇。单纯改文案不触发生成。已有满意音频或已确认剪辑继续复用。若本期不适合工作台，记录具体原因，不强行迁移。

当前实例只维护一个工程。试用新视频前先导出旧工程 ZIP；导入默认追加，不能把追加误认为创建或切换独立工程。用清楚的章节名称区分本次试用，避免将旧视频句段一起连播或混音导出。多工程管理尚待实现。

1. 确认文稿、表现方向及画面证据；TXT / Markdown 可按标题拆章、章内拆句，JSON / ZIP 使用 v2 合同。
2. 保留「工程 → 章节 → 句段」层级；同一句段节点拥有旁白与画面，不拆成两套图。已有句段可继续拆分；原稿和素材保留并停用，不自动切割音视频。
3. 先试听一个关键短段，确认音色、语气与停顿。保存后显式创建句段任务，导出交接清单。浏览器网页执行、未来 API 执行、已有素材导入，都回填到相同句段与素材版本体系。
4. 目前由 Codex 或用户在已授权网页执行；按任务快照生成，下载结果，实测时长，绑定对应 jobId 导入。任务创建本身不会调用外部服务。
5. 在节点内预览音画，评论绑定版本和时间点；选择问题评论显式创建返修任务。只重做受影响句段，保留已通过版本；晚到结果不能静默覆盖新版本。
6. 调整句段音量、总音量及停顿，按章节和启用句段顺序连续预览。解决意见后人工验收。声音全部通过后可导出 WAV，并保存完整 ZIP。
7. 当前精细剪辑时间线和 MP4 合成未实现。成片继续交给已授权剪辑工具，使用实际选定的素材版本，重新验证字幕、音画同步与转场。

## 配音执行通道

| 通道 | 当前状态 | 使用方式 |
| --- | --- | --- |
| MiniMax Audio 网页 | 当前默认外部执行路径 | 复用已授权登录与本人音色，核对实际余额、试听后生成，再绑定任务回填 |
| MiniMax 开放平台 API | 官方具备能力，本仓库尚未接入、未做账户实测 | 先验证账户、本人音色可用性和额度／计费，再考虑后端适配器 |
| 已有音频文件 | 已支持 | 可直接导入；对应生成任务的结果应绑定 jobId，保留来源与快照 |

2026-10-16 已核对官方[同步语音合成文档](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)与[国际站文档](https://platform.minimax.io/docs/api-reference/speech-t2a-http)：提供 `POST /v1/t2a_v2`，使用 Bearer API Key、模型、文本、voice_setting 等参数。接口存在不等于当前网页账户可直接使用。

以下仍未验证：网页已保存音色能否出现在目标 API 账户并用于合成、网页赠送额度是否可用于 API、当前账户 API 计费及可用模型、相同音色和参数下的实际听感。不要把这些当成已支持，也不从网页抓取私有接口作为公开 API 替代品。当前继续沿用网页路径；不会因网页操作耗时就自动建密钥、重新克隆或切到付费 API。

未来 API 接入先做一个已授权短句试验，比较本人音色、停顿、语速、响度与费用。只有证据充分且已获对应授权，才扩大到后续句段。密钥仅进入服务端本地配置，不进入浏览器、工程 JSON、交接清单或 Git。具体接入区域、模型与音色由适配器处理，领域节点与审阅逻辑不增加 MiniMax 专用分支。

后台 worker 尚未实现。接入时需补充任务领取与去重、取消检查、超时后的状态核对、真实失败信息及调用／用量证据；超时不自动盲重试。执行证据扩展必须经过正式格式版本演进，不能塞入当前严格 v2 工程中充当兼容字段。

## 每次试用留下什么

可在本地 `data/runs/<日期>-<本期名称>.md` 按下表记录；该目录被 Git 忽略。不得声称整条工作流已验证，除非对应步骤确实完成。

| 项目 | 记录内容 |
| --- | --- |
| 本次范围 | 工程 ID、试用章节／句段 ID、版本及任务 ID |
| 配音执行 | 网页／API／已有文件，实际模型与设置、用量或费用；未知则写未知 |
| 试听与返修 | 问题版本、评论定位、返修结果；是否发生过期回填 |
| 连续预览 | 句段顺序、停顿、音量、音画同步及断句是否自然 |
| 导出与恢复 | WAV 解码、ZIP 下载和重新导入的实际结果 |
| 结论 | 可扩大使用／需修复／本期跳过；问题证据与下一步 |

首轮真实试用重点观察：逐句生成是否损害上下文语气、相邻句音色与响度是否稳定、返修能否保持衔接，以及网页下载和任务回填是否繁琐。若逐句听感不自然，可保留较长句段生成，再按审阅需要拆分；不能把“更细”直接当作“更自然”。
